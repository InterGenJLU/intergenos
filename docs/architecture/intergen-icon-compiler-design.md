# InterGenOS Icon Compiler (IGIC) — design + executable specification

**Status:** v0.3 — executable-grade spec, backed by a working prototype (revised 2026-07-10).
Supersedes the v0.1 vision doc (2026-06-29): the phasing, decisions, and aesthetic
basis are carried forward unchanged; this revision pins every input, output,
dependency, invocation, and failure mode to what the prototype actually does, so a
reader can run it and get identical results. **Rule 21 honored:** every mechanism named
below is either implemented in the prototype (marked **BUILT**) or explicitly marked
**SPEC-ONLY** / **Phase-2** — nothing named is a silent stub. The BUILT-vs-SPEC-ONLY
ledger is §19.
**Aesthetic basis:** `docs/VISUAL_LANGUAGE.md` **v2** — icons are **flat + color +
baked ECG-blue glow signature, NOT glass** (VL §11). This doc grounds ONLY in
VISUAL_LANGUAGE.md v2 and itself.
**Prototype:** the reference implementation is the `igic/` tree delivered alongside
this doc; `RUN.md` gives the exact commands. The prototype renders the 7 VL anchor
icons + folder color-coding + a symbolic icon + the pulse signature, end to end.

---

## 1. Purpose + the determinism principle

A deterministic asset pipeline that compiles the InterGenOS icon theme from a small
library of reusable primitives (palette + glyphs + templates) and per-icon recipes,
instead of hand-maintaining hundreds of SVGs. Icons become a **build product with
embedded provenance** — source → compile → verify → reproducible artifact, the same
identity the distro is built on.

**Determinism is a load-bearing property, not a nicety.** Same recipe + glyph +
palette bytes MUST produce a byte-identical SVG on every machine and every run. No
wall-clock, no RNG, no locale-dependent formatting anywhere in the compiler. This is
what makes the Phase-2 CI regenerate-and-diff gate (§20.5) possible: a shared-rule
change (e.g. the glow) ripples to every icon and the diff shows exactly which outputs
moved. The prototype proves determinism by regenerate-and-diff (`RUN.md` step 5).

**Consequence for provenance (§12):** the embedded provenance is **content-addressed
(sha256), never time-stamped** — a build timestamp would break byte-determinism. Build
time, if wanted, lives in a human-facing narration line, not in the committed asset.

## 2. Not greenfield — the established house pattern

VISUAL_LANGUAGE.md §15 already establishes that vector assets are generated by Python
+ **cairosvg** from committed source, regenerable with one command. The **logo mark
already works this way** (`assets/intergen-mark/generate.py`: `make_svg()` string
assembly → `cairosvg.svg2png()`, hybrid size routing, clean-slate regeneration). IGIC
is an **extension of that proven pattern** — same renderer, same string-assembly-then-
raster shape — generalized from one mark to a recipe-driven set with validation gates,
provenance, and a freedesktop-theme exporter. It is not a new dependency class.

## 3. Repository layout

**Prototype tree (BUILT — the delivered `igic/`):**
```
igic/
  palette.yaml            # controlled palette: VL §4 tokens + folder/MIME accent set
  igic_core.py            # library: palette, safe parser, both gates, glyph load/
                          #   sanitize/extract, template/pulse/glow geometry,
                          #   provenance, compositor
  validate_icons.py       # standalone two-gate validator (CLI, importable)
  build_icons.py          # the compiler CLI: recipes -> validated theme + samples
  glyphs/                 # colorless monochrome geometry, one SVG per glyph
    terminal.svg gear.svg document.svg globe.svg grid.svg trash.svg
    emblem-doc.svg emblem-download.svg
  recipes/                # one YAML per icon (11 shipped)
    org.intergenos.terminal.yaml  folder.yaml  folder-documents.yaml  ...
```
**In-tree target layout (SPEC-ONLY — where it lands):** the tool tree goes to
`assets/intergen-icons/` (data: `palette.yaml`, `glyphs/`, `recipes/`) with the three
Python modules under that dir or `tools/icons/`, mirroring `assets/intergen-mark/`. The
compiled theme is the packaged artifact (§20.3), not the compiler.

| Dependency | Version verified | Role | Required for |
|---|---|---|---|
| python3 | 3.12.3 | runtime | all |
| cairosvg | 2.9.0 | SVG→PNG raster | `build_icons.py` raster + contact sheet |
| PyYAML | 6.0.3 | recipe + palette parse | all |
| lxml | 6.0.2 | safe SVG parse + sanitization | both gates |
| Pillow | 10.2.0 | contact-sheet composition only | `build_icons.py` without `--no-sheet` |

`validate_icons.py` needs only python3 + PyYAML + lxml (no cairosvg, no Pillow — it
rasterizes nothing). Install: `pip install --user cairosvg PyYAML lxml Pillow`
(matches the mark generator's `pip install --user cairosvg`). No network at build time;
no external binaries (`rsvg-convert`/`inkscape` are NOT used).

## 5. The controlled palette (`palette.yaml`)

`tokens:` mirror VISUAL_LANGUAGE.md §4 verbatim (authoritative canon — a change is a
canon change, made in VISUAL_LANGUAGE.md first, then mirrored). `accents:` are the
folder / MIME color-coding set. **BUILT** with a defensible starter accent set;
**reserved:** the authoritative accent enumeration is reserved for the maintainer
in a companion `ICON_CATEGORIES.md` (v0.1 §10.2), which supersedes the starter set by
editing `palette.yaml` — no code change. The starter set includes `accent-yellow`
`#ffd23f`, deliberately **distinct from warning amber `#f59e0b`** so a yellow folder
never reads as a warning (the §10.2 mandate). A recipe may name ONLY a palette token;
an unknown token fails closed (§13 gate 1).

## 6. The recipe schema (v1, pinned)

One YAML file per icon — data, not code; adding/altering an icon is a recipe edit.

| Field | Type / enum | Required | Default | Meaning |
|---|---|---|---|---|
| `schema_version` | int `1` | yes | — | schema version; must be `1` |
| `id` | slug `^[a-z0-9][a-z0-9._-]*$`, unique | yes | — | icon id; last dotted segment is the theme filename stem |
| `name` | string | yes | — | human name (report + contact sheet) |
| `category` | `apps`\|`places`\|`mimetypes`\|`devices`\|`status`\|`actions` | yes | — | freedesktop context |
| `kind` | `color`\|`symbolic` | no | `color` | color = palette color + glow; symbolic = off-white monochrome |
| `template` | `none`\|`app-tile`\|`folder` | no | `none` | base silhouette (color icons); symbolic forces `none` |
| `glyph` | glyph name (file `glyphs/<glyph>.svg`) | conditional | — | required unless the icon is template-only or pulse-only |
| `color` | palette token | no | `ecg-blue` | color-icon stroke/accent color |
| `accent` | palette token | no | `ecg-blue` | symbolic accent token |
| `glow` | `none`\|`signature` | no | `none` | baked ECG-blue edge glow (color icons, detailed variant) |
| `pulse` | `none`\|`bottom`\|`primary` | no | `none` | bake the pulse motif |
| `export.svg` | bool | no | `true` | emit the scalable SVG |
| `export.png` | list ⊂ {16,24,32,48,64,128,256} | no | `[]` | raster sizes to emit |

Content rule (BUILT): a `color` icon with `template: none` and no `glyph` is valid ONLY
if `pulse` is set (the pulse is then the icon — the system-monitor case). A `symbolic`
icon requires a `glyph`.

## 7. The glyph contract (pinned)

A glyph is **colorless monochrome geometry** the compiler colors — it is the AI-
draftable unit (§18). Hard contract, enforced by the gates:
- Root `viewBox` is exactly `0 0 256 256` (VL §7/§11 canvas). **BUILT** gate.
- Only VL §7 primitives: `path rect circle line polyline polygon ellipse` (+ a `<g>`
  wrapper). Anything else is a gate-1 structural reject. **BUILT.**
- No color: the compiler strips any `stroke`/`fill`/`stroke-width`/`style`/`class`/
  `opacity` and re-emits geometry with `fill="none"` and the recipe's stroke. **BUILT.**
- Content within the 16% safe area (`[40,216]`) — authored-in, checked approximately
  (§13). **BUILT (approximate); precise stroke-aware bbox is Phase-2.**
- Passes gate 2 security (§13) before any use. **BUILT.**

## 8. Templates (pinned)

Base silhouettes the compiler draws, color-stripped, then strokes in the recipe color
over a dark `bg-card` body:
- `none` — no container; the glyph (or pulse) is the whole icon. **BUILT.**
- `app-tile` — a rounded container (radius scaled from VL §7's 14px app-icon
  container). **BUILT.**
- `folder` — a front-facing folder silhouette: a clean single-edge outline (no top-left notch) with a raised tab.
  **BUILT.** The dark-body-with-accent-stroke rendering is one defensible reading of VL
  §11 ("folder variants differentiate by accent color + a small emblematic glyph"); the
  exact folder treatment (dark-body-glow vs color-fill) is an **operator creative call**
  settled in `ICON_CATEGORIES.md`, swappable by editing `template_elements()`.

Templates are code built-ins in the prototype. Authoring templates as sanitized SVG
files (like glyphs) is **Phase-2** — the compositor would treat a template name as
either a built-in or a sanitized `templates/<name>.svg`.

## 9. The pulse motif (pinned; VL §8)

The ECG pulse — the signature "system is alive" cue, from the VL §8 canonical QRST
geometry. The layout is **asymmetric by construction** — a SHORT lead-in on the left, the
spike LEFT-of-center, a LONG baseline tail to the right (assets/intergen-mark/README.md:13;
VL §8) — enforced as a **hard conformance property**: the single `pulse_path()` source
asserts tail>lead and spike-left-of-center, so a centered spike cannot silently ship.
- `bottom` — a restrained but abrupt spike low under a glyph, inside the safe area
  (y-range 126–200); a tall-narrow miniature of the `primary` character with a
  near-vertical R-wave (its own narrow x-layout, so `primary` is untouched). Used on
  the terminal ("a pulse line across the bottom", VL §8). **BUILT.**
- `primary` — the full signal; the pulse IS the icon (system-monitor / activity).
  **BUILT.**
The pulse is always ECG blue `#0099FF` (VL §8). Animated pulse variants (activity /
busy) are **Phase-2** (a static frame is BUILT).

## 10. The baked glow signature (pinned; VL §11.4)

VL §6/§10 forbid a baked tint on shell widgets (glow on interaction only); VL §11.4
grants icons the **one scoped exception** — a *baked* ECG-blue edge glow, because an
icon is a static asset that must carry the brand cue at rest. **BUILT** as an
`feGaussianBlur` filter applied to an ECG-blue, blurred copy of the mark outline behind
the mark (`opacity 0.55`). All colors stay on-palette; the softness is a filter, not a
color, so the palette-only gate (§13) still passes. Emitted on the **detailed** variant
of color icons whose recipe sets `glow: signature`; dropped on the simplified small-size
variant (VL §11 small-size rule). **Renderer note:** cairosvg renders the blur; a
renderer with no filter support degrades to a crisp offset edge (the SVG carries the
correct blur regardless) — a documented, non-fatal degradation.

## 11. Compositing algorithm (pinned, ordered layer stack)

For a recipe + variant (`detailed`|`simple`), `compose_icon()` emits, in order:
1. `<svg viewBox="0 0 256 256">` root.
2. `<defs>` with the glow filter — only if `glow: signature` and variant `detailed`.
3. `<metadata>` provenance block (§12).
4. Template body fill (`bg-card`) — only for `app-tile`/`folder`.
5. Glow group — an ECG-blue, blurred copy of (template outline + glyph) — detailed +
   glow only.
6. The mark — template outline + glyph, stroked in the recipe color (color) or off-
   white (symbolic), round caps/joins, `fill=none`.
7. The pulse path — if `pulse` set, stroked ECG blue.

Stroke width: `detailed` = 5px (~2% of the 256 canvas), `simple` = 16px (~6%) — VL §6 lines 248/250 + the mark's 10/512 · 32/512. (VL §11's anatomy table lists 12px/24px, which conflicts with §6 and reads too heavy; §6 + the mark are authoritative — the §11 table is flagged to reconcile.) Symbolic icons
skip steps 2/5 (no glow) and stroke in off-white `#e2e8f0`.

## 12. Provenance (pinned; content-addressed, timestamp-free)

Every composed SVG embeds:
```xml
<metadata><igic:provenance xmlns:igic="https://intergenos.org/ns/igic/1"
  compiler="igic 0.2.0-prototype" recipe-id="..." recipe-sha256="..."
  glyph="..." glyph-sha256="..." palette-sha256="..." canvas="256" variant="..."/></metadata>
```
No timestamp (determinism, §1). Any rendered asset answers "exactly how was I built?"
from its recipe/glyph/palette hashes + compiler version. **BUILT.**

## 13. The two validation gates (pinned; fail-closed)

Both gates run on glyph **inputs** and on the composed **output**. Any hit = the asset
never ships (fail-closed). `validate_icons.py` runs them standalone; `build_icons.py`
runs them inline and refuses to emit a failing icon.

**Gate 1 — spec compliance (BUILT):**
1. `schema_version == 1`. 2. `id` matches the slug regex + is unique. 3. `category` in
the freedesktop set. 4. `kind` valid. 5. `color`/`accent` tokens resolve in the palette.
6. `template`/`glow`/`pulse` in their enum sets. 7. glyph file exists when required.
8. `export.png` ⊂ the allowed size set. 9. composed `viewBox == "0 0 256 256"`.
10. composed node count ≤ 500 (runaway-SVG guard). 11. `igic:provenance` present.
12. **palette-only** — every explicit `stroke`/`fill`/`stop-color`/`flood-color`/`color`
is a palette hex, `none`, `currentColor`, or an internal `url(#…)`; any off-palette
color fails. 13. all geometry coordinates within the canvas `[0,256]` (HARD). The
precise stroke-aware **16% safe-area** bbox is **Phase-2**; the prototype relies on
authored-in margins + the within-canvas check.

**Gate 2 — security sanitization (BUILT; the load-bearing security addition — we ship
AI-authored SVG):** reject `<script>`, `<foreignObject>`, `<image>`; any `on*` event-
handler attribute; any `href`/`xlink:href` not starting `#` (external ref); any `<use>`
with external/absent href; any `url(...)` whose target is not an internal `#` fragment;
any `javascript:` URI; and any `DOCTYPE`/DTD (XXE surface — the parser also runs with
no network, no DTD load, no entity resolution). Verified biting on hostile inputs
(`RUN.md` step 4: script/onload/image/external-href/use-external/external-url and a
DOCTYPE/XXE file are all rejected).

## 14. Rasterization + hybrid size routing (pinned)

`build_icons.py` rasterizes each emitted size with cairosvg. **Hybrid routing (BUILT):**
target sizes ≤ 48 render from the **simplified** variant (16px stroke, glow dropped);
sizes ≥ 64 render from the **detailed** variant (5px stroke, glow) — the logo mark's own
routing. Threshold `SIMPLIFY_AT = 48`. The simplified variant is stroke-thickening +
glow-drop on the SAME
geometry; per-icon **reduced-geometry** simplified glyphs are **Phase-2** (the VL §6
"reduced geometry" half).

## 15. Export: the freedesktop theme (pinned)

**BUILT.** Emits `out/theme/InterGenOS/`:
- `scalable/<context>/<stem>.svg` — the detailed composed SVG.
- `<size>x<size>/<context>/<stem>.png` — rasterized per recipe `export.png`.
- `index.theme` — `[Icon Theme]` with `Inherits=Adwaita,hicolor` (VL §6 / v0.1 §6: ship
  the core set, inherit the long tail), a `Directories=` list, and a per-directory
  `[dir]` block (Size/Type/Context; scalable dirs carry MinSize/MaxSize).
- Symbolic icons take the freedesktop `-symbolic` filename suffix.

`<stem>` is the recipe `id`'s last dotted segment (`org.intergenos.terminal` →
`terminal.svg`). Mapping stems to exact freedesktop **standard icon names** (so the
theme resolves for arbitrary apps/mimetypes) is a **Phase-2** mapping table; the
prototype uses recognizable names.

## 16. Invocation (pinned; exact commands in RUN.md)

- `python3 assets/theming/igic/validate_icons.py` — validate every
  recipe + its composed output (both gates). Exit 0 clean / 1 on any violation.
- `python3 .../igic/validate_icons.py FILE.svg ...` — gate arbitrary SVG file(s).
- `python3 .../igic/build_icons.py [--out DIR] [--clean] [--no-sheet]` — compile the
  theme + `build-report.json` + `contact-sheet.png`. Exit 0 clean / 1 if any icon
  failed a gate. Default `--out` = `../out`.

## 17. Failure modes (enumerated)

| Condition | Behavior |
|---|---|
| unknown color/accent token | gate 1 reject; icon not emitted; build exit 1 |
| glyph file missing | gate 1 reject (references a non-existent glyph) |
| glyph carries `<script>`/handler/external ref/`<image>`/DOCTYPE | gate 2 reject; icon not emitted |
| glyph non-primitive element (e.g. `<text>`) | gate 1 structural reject |
| glyph wrong viewBox | gate 1 reject |
| composed SVG off-palette color | gate 1 reject (guards a compositor regression) |
| composed node count > 500 | gate 1 reject |
| recipe `export.png` size outside the allowed set | gate 1 reject |
| template-less, glyph-less, pulse-less color icon | gate 1 reject (empty icon) |
| cairosvg absent | `build_icons.py` import error (documented dep, §4); `validate_icons.py` still runs |
| Pillow absent | run `build_icons.py --no-sheet` (theme still builds) |

Every failure is fail-closed: a bad asset is never emitted, and the build exits non-zero
so a caller (or the Phase-2 CI gate) sees it.

## 18. AI's scoped role (pinned to the gates)

Unchanged posture (v0.1 §8): AI assists, never ships release art directly. It may draft
**glyph candidates** (the §7 contract: primitives only, no color/effects), **recipes**
(YAML), and metadata. Human review is mandatory; **gate 2 (§13) is what makes shipping
AI-authored SVG safe** — every drafted glyph is sanitized before use, and the compiler +
gates enforce consistency and safety regardless of draft quality.

## 19. BUILT vs SPEC-ONLY ledger (Rule 21)

**BUILT in the prototype (runs today on this box):** palette load + token resolve;
recipe schema v1 + gate-1 recipe validation; glyph load + gate-2 sanitize + gate-1
structural + color-strip extract; templates none/app-tile/folder; pulse none/bottom/
primary; the baked glow signature filter; the compositor (detailed + simplified);
gate 1 + gate 2 on composed output (fail-closed); cairosvg raster + hybrid size routing;
freedesktop theme export + `index.theme` + `Inherits=Adwaita,hicolor` + `-symbolic`
suffix; content-addressed timestamp-free provenance; deterministic `build-report.json`;
the `contact-sheet.png` iteration lever; 8 glyphs + 11 recipes covering the 7 VL anchors
+ folder color-coding + a symbolic icon + the pulse signature; proven determinism;
proven gate-2 biting on hostile input.

**SPEC-ONLY / Phase-2 (specified above; the prototype does not implement):** precise
stroke-aware 16%-safe-area bbox gate (prototype: within-canvas + authored margins);
per-icon reduced-geometry simplified glyphs (prototype: stroke/glow adaptation only);
templates authored as sanitized SVG files (prototype: code built-ins); per-glyph
symbolic accent-region placement (prototype: whole-glyph off-white); CI regenerate-and-
diff wiring (the determinism it needs is BUILT + proven); freedesktop standard-icon-name
mapping table; the animated pulse frames; the authoritative `ICON_CATEGORIES.md` accent
enumeration (operator creative call; prototype ships a defensible starter set). None
blocks the core path; each is an additive layer on a working base.

## 20. Decisions carried from v0.1 §10 (unchanged)

1. **Name** — IGIC / InterGenOS Icon Compiler.
2. **Accent palette** — a small curated set including a yellow distinct from warning
   amber; enumerated authoritatively in `ICON_CATEGORIES.md` (operator). Prototype ships
   a starter set (§5).
3. **Packaging** — build-time tooling, NOT a shipped package; the compiled theme is the
   packaged artifact.
4. **Scope** — symbolic/system icons + pulse indicators are a co-equal Phase-1 target
   (both tracks are BUILT in the prototype).
5. **CI regenerate-and-diff** — adopt at Phase-2; the determinism it depends on is BUILT
   and proven now.

## 21. Placement + phasing

Pre-RC001-arc (v0.1 §11). **Phase 1 — prove the look on both tracks + the pulse:** the
prototype does this end to end (color anchors, the symbolic track, the pulse signature),
with `contact-sheet.png` as the taste-iteration lever. **Phase 2 — harden the compiler**
around what proves out (the SPEC-ONLY items in §19), then batch-generate the core sets.
**Phase 3 — coverage** grows recipe-by-recipe; the long tail inherits from Adwaita/
hicolor (release-realistic — do not block RC on full coverage). Nothing here is on the
9B model track.
