# Physical-hardware driver classes that must be PRESENT in the produced kernel.
#
# Read by scripts/check-kernel-required-symbols.py, which both kernel recipes run
# after merging the config fragments. These are asserted as ENABLED (=y or =m)
# rather than at an exact value: for a driver, module-versus-built-in is a
# legitimate packaging choice, while ABSENCE is the defect.
#
# WHY THIS EXISTS, measured in the shipped tree: the baseline fragment requested
# THIRTEEN CONFIG_MMC_* host-controller drivers but never requested the parent
# symbol they all depend on (`menuconfig MMC`). `make olddefconfig` silently
# discarded all thirteen and wrote "# CONFIG_MMC is not set". The recipe looked
# like it asked for a card reader; the produced kernel had no MMC subsystem at
# all; nothing failed. Evaluations run in virtual machines, which have no SD card
# reader, no I2C-HID touchpad and no on-board audio codec — so a kernel missing
# every one of those drivers passes every automated check and fails on the first
# real laptop.
#
# The list moved out of the recipes and into this file on 2026-08-11 so both
# kernel passes assert it from one place. Decided 2026-08-07.
#
# Format: one CONFIG_X name per entry, no value. Comments and blanks ignored.
