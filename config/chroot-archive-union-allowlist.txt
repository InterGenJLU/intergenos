# chroot-archive-union allowlist — files legitimately present in the built
# chroot that NO sealed archive should ever carry. Consumed by
# scripts/check-chroot-archive-union.py (build pre-flight gate).

# Format: <pattern><TAB or 2+ spaces><reason>. Three pattern forms:
# exact path, `dir/**` subtree prefix, fnmatch glob. An entry without a
# reason refuses the gate (same engine as the Step 4.85 allowlist).
#
# Discipline: this list holds STRUCTURAL classes only — state a mechanism,
# not a package. Per-finding additions from real firings carry a date in

# first real firing against a build substrate dispositions the remainder
# per-finding (the same way the Step 4.85 allowlist was built).

# ---- bootstrap (temporary) toolchain residue -------------------------------
# Decided 2026-08-19: these are covered here rather than removed, and the
# reason is that removing them changes which assembler, linker and fixed
# headers the compiler selects for every package built afterwards. The
# compiler searches its own prefix directory before the system one, so a
# deletion mid-cycle would silently move every subsequent compile onto
# different tools. That is the opposite of what this gate is for.
#
# What the measurement established: the final binutils recipe installs with
# tooldir=/usr and never populates the target prefix, and the final gcc recipe
# configures --disable-fixincludes, so neither of those trees can hold current
# payload — every path reported under them is left over from the temporary
# toolchain built before the package system existed. The gcc entries are
# scoped to the two subtrees that appeared, NOT to usr/lib/gcc as a whole,
# because the rest of that tree is current payload the archives do carry and
# the gate must keep watching it.
#
# The disposition owed was MEASURED 2026-08-19 (R001.1 pre-flight, in the real
# chroot): the target-prefix assembler and linker are NOT byte-identical to
# their /usr/bin counterparts (all four hashes differ). Per this note's own
# rule, the difference is a recorded finding and the residue is not resolvable
# by deletion — the tree stays covered by the entry below and stays watched.
usr/x86_64-igos-linux-gnu/**	temporary-toolchain target-prefix tree (target-prefixed tool copies and linker scripts) — the final binutils installs with tooldir=/usr and never populates it; the note above records why measurement rules out deleting it
usr/lib/gcc/*/*/include-fixed/**	temporary-toolchain fixincludes output — the final gcc configures --disable-fixincludes and cannot produce it
usr/lib/gcc/*/*/install-tools/**	temporary-toolchain fixincludes support files — same reason
usr/libexec/gcc/*/*/install-tools/**	temporary-toolchain fixincludes tooling — same reason
